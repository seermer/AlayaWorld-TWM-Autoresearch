# live-11-08: animal benchmark on H100

Assume the AutoResearcher README setup is complete, with all three repositories
on `live-11-08`. Run these commands from `WM-AutoResearch/AutoResearcher`, with
`.envs/autoresearcher` activated and `HF_HOME` set as in the README. This profile
requires eight idle H100 80 GB GPUs and the host resources listed there.

## Prevent run uploads before launching

Set `HFK=` in `AutoResearcher/.env` and remove any exported shell value with
`unset HFK`. **Check both sources**: an empty shell variable does not override a
nonempty `.env` value. Keep the read-only Hugging Face login for downloads;
`HFK` controls the run archive uploads. This check prints no token:

```bash
unset HFK
python - <<'PY_CHECK'
import os
from pathlib import Path
from dotenv import dotenv_values
assert not os.environ.get("HFK", "").strip(), "Shell HFK must be empty"
assert not (dotenv_values(Path(".env"), interpolate=False).get("HFK") or "").strip(), \
    ".env HFK must be empty"
print("HFK upload disabled in shell and .env")
PY_CHECK
```

**Do not pass `--git-remote`** to `ar run`, or expand a `$REMOTE` into the
command. Without that option, a new run keeps agent branches locally. The source
repositories' `origin` remotes can remain for fetching code; they are distinct
from the run's optional GitHub backup remote. Use a new run ID: a resumed run
can restore a previously saved `git_remote` from its run arguments. Do not use
`ar upload` or an upload wrapper such as `scripts/sbatch_run.sh` for this recipe.

## Check and launch

Apply the H100 config first, then the animal config, consistently for downloads,
checks and launch. Finish the README's GPU preflight on a new machine as well.
Commit any local edits in all three repositories before starting.

```bash
python scripts/download_weights.py --config configs/h100.yaml configs/animal_appears.yaml
python scripts/download_weights.py --check --config configs/h100.yaml configs/animal_appears.yaml
ar doctor --gpu --config configs/h100.yaml configs/animal_appears.yaml
# Continue only when checks pass.
unset CUDA_VISIBLE_DEVICES
unset REMOTE
export RUN=animal-h100-live-11-08-01  # choose a fresh name
mkdir -p runs
test ! -e "runs/$RUN" || { echo "Choose a new RUN"; exit 1; }
nohup ar run --run-id "$RUN" --max-nodes 6 \
  --config configs/h100.yaml configs/animal_appears.yaml \
  > "runs/$RUN.console.log" 2>&1 &
```

## Use the simple panel

In a second terminal, follow the README's terminal setup and set `RUN` to the
same run ID. Create the panel environment once and choose your own login:

```bash
scripts/setup_envs.sh simple-panel
(umask 077; printf 'viewer:REPLACE_WITH_A_STRONG_PASSWORD\n' > .simple_panel_auth)
.envs/simple-panel/bin/python -m simple_panel --run-id "$RUN" --no-share
```

`--no-share` disables the public Gradio share tunnel. The panel listens on the
server's network interfaces; use a trusted network or SSH forwarding
(`ssh -L 7860:127.0.0.1:7860 <user>@<server>`, then open
http://127.0.0.1:7860). Keep `--no-share` when avoiding external panel sharing.
Refresh takes a new scrubbed snapshot. Check progress with
`ar status --run-id "$RUN"` and `tail -f "runs/$RUN.console.log"`.
